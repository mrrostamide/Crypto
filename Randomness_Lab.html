Level 1: Same seed, same numbers

A pseudo-random number generator (PRNG) is a machine that makes numbers that look random. In this level you will see that it follows a rule, and that anyone who knows the rule and the start number can predict every number.

What is a seed?

The seed is the number where the machine starts. The machine takes the seed, applies a rule, and gets the first number. Then it applies the same rule to that number to get the next one, and so on.

1Meet the machine

Our machine uses a very old rule, the middle-square method. For every number it does three things:

  1. Multiply the number by itself.
  2. Write the result with 4 digits (add zeros at the front if needed).
  3. Take the middle two digits. This is the next number.
Show me an example

Start with 42. 42 x 42 = 1764. The four digits are 1 7 6 4. The middle two digits are 76. So the next number is 76.

Now start with 5. 5 x 5 = 25. With 4 digits this is 0025. The middle two digits are 02. So the next number is 02.

4Think like Eve

Eve is an attacker. She knows the rule of the machine and the seed. What can she do?

Why is the rule not secret?

In cryptology we always assume that the attacker knows the rule (the algorithm). Only the key, or here the seed, can be secret. This is Kerckhoffs's principle from Session 1.

Level 1 complete! A PRNG is only a rule: the same seed always gives the same numbers. Next: how do we count how unpredictable a seed is? Try Level 2.

Level 2: Count the bits

A key is only strong if nobody can guess it. Entropy measures how hard something is to guess, and we count it in bits. In this level you learn to count bits.

What is entropy?

Entropy is the amount of unpredictability. One fair coin flip has 1 bit: there are two results, heads or tails, and nobody can guess better than 50 %. The more possible results, the more bits.

2From possibilities to bits

Often we know the number of possibilities and want the bits. The rule: bits = how many times you double 1 to reach that number. Example: 1,024 possibilities = 10 bits, because 210 = 1,024.

Level 3: The clock problem

The story. Alice wrote a program that makes a 128-bit secret key. To get a "random" key, the program uses the time of day in seconds as the seed of a PRNG. You are Eve. You know that the key was made today, but you do not know the exact time.

A 128-bit key has 2128 possible values. That is far too many to try. But how many seeds are possible?

How many seconds are in a day?

24 hours x 60 minutes x 60 seconds = 86,400 seconds. So today there are only 86,400 possible seeds, and only 86,400 possible keys.

Why does Eve know a fingerprint?

In a real attack Eve tests each candidate key on the encrypted message. If the message becomes readable, the key is right. To keep this game simple, we let Eve compare the first 12 hex digits of each candidate key with the fingerprint. The idea is the same.

2Eve's method: guess, calculate, compare

Eve does not know the time. But she has the public program and the fingerprint. So she works in three steps:

If the digits are the same, the guessed time is the real time. If they are different, Eve tries another time. Try one guess yourself:

What you learn: Eve can test any guess in one calculation, but there are 86,400 possible times. A lucky guess almost never works (1 chance in 86,400).

3The computer repeats it for every second

Trying one guess is easy, but trying 86,400 by hand is not. A computer does the same three steps for 00:00:00, then 00:00:01, then 00:00:02, and so on. It stops when the digits match the fingerprint.

What you learn: there are only 86,400 seeds, so a computer can test all of them in a fraction of a second. The long 128-bit key does not protect Alice.

Does the computer know the secret time?

No. Eve's attack never sees Alice's real time. It only tries one time after another and compares each calculated key with the fingerprint. When one time gives the same digits as the fingerprint, the attack has found Alice's time. The game then shows you this time and the full key, as the result of the attack.

4How strong is the key really?

The key looks like 128 bits. How many bits of real strength does it have?

What does "bits of strength" mean?

n bits of strength means about 2n possibilities for the attacker to try. 86,400 possibilities is about 216.4, so the key is as weak as a 16-bit key, even if it is written with 128 bits.

5Fix the problem

Alice reads the guide and changes her program. Now it takes the key from the secure random generator of the computer (not from the clock).

What is a secure random generator?

It is a generator designed for keys. The operating system collects unpredictable data (for example from hardware events) and uses it as a seed with lots of real entropy. Then nobody can guess the seed. In a browser it is called crypto.getRandomValues. In Python it is the secrets module.

Now run Eve's attack again (step 3) against the new key.

Level 3 complete! A long key is not enough. The key is only as strong as the seed it comes from. Next: a real case with the same problem. Try Level 4.

Level 4: The Debian bug

The real story. In 2006 a developer of the Debian Linux distribution removed two lines of code from the OpenSSL library, because a code-checking tool gave a warning. Those lines added random data to the key generator. After the change, the generator was seeded almost only with the process ID. The problem was announced in May 2008, and all affected keys had to be replaced.

In this level you play a toy version of this bug and see why it was so serious.

What is a process ID?

Every running program gets a number from the operating system. This is its process ID. On Linux of that time it was a number from 1 to 32,767. It is not secret and it is not random.

1Count the keys

The toy generator takes the process ID (1 to 32,767) as its seed and makes a 128-bit key from it. How many different keys can this generator make?

Hint

One seed gives exactly one key. So the number of keys is the same as the number of different seeds.

2Make the list of all keys

You are an attacker. The program is public, so you can calculate the key for every process ID in advance and keep them in a list.

What you learn: 32,767 keys is a short list. A normal computer builds it in a fraction of a second.

Level 5: Fix it

You know the problem. Now choose the safe solution. There are four short rounds.

Where do I find a secure random generator?

Every common platform has one. These lines make 16 random bytes (128 bits):

Python: secrets.token_bytes(16)
Java: new SecureRandom().nextBytes(key)
JavaScript (browser): crypto.getRandomValues(new Uint8Array(16))
Linux shell: head -c 16 /dev/urandom

Level 5 complete! Three rules to remember:
1. Make keys with the secure random generator of the operating system.

3. If a key generator was flawed, replace all keys it made.
