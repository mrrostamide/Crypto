What really happens when you type ssh?

A user named student logs in to a Linux server with an SSH key. The user runs one command, echo Hello, and then leaves.

We recorded this session with a packet sniffer. The capture has 63 packets. In this tutorial you follow them one by one: from the first TCP packet to the last.

Client192.168.1.10 : 50122
SSH over TCP
port 22
Server192.168.1.20 : 22

You will learn

  • How the client and the server agree on algorithms
  • How they create a shared secret with ECDH (curve25519)
  • How the server proves its identity (host key)
  • How the client proves its identity (user key)
  • What an observer can and cannot see in encrypted traffic

How to use this page

  1. Open Walkthrough and go through the 12 steps.
  2. In each step, click the packets and fields. The bytes light up, as in Wireshark.
  3. Use the switch Decrypt with key log to see the traffic with and without the key.
  4. Answer the short question at the end of each step.

Open the same file in real Wireshark

Download the capture: ssh_ed25519_aes128gcm_port22.pcapng (9 KB).

The file already contains the decryption key (a "key log" stored inside the pcapng file). A current Wireshark version (4.x) reads it on its own, so you will see the decrypted SSH messages. The key is the server's temporary curve25519 private key. It is valid for this one session only.

Useful display filters: ssh, tcp.len > 0, ssh.message_code == 50. You can try the same filters in the tab Explore the Capture.

The whole session on one page

SSH is not one protocol. It is three layers on top of each other. Each layer starts only when the layer below has finished its job.

Layer (RFC)JobFramesResult
Transport (RFC 4253)Agree on algorithms, create keys, authenticate the server, encrypt everything4 – 17Encrypted channel with a verified server
User authentication (RFC 4252)Authenticate the client user18 – 37User student is logged in
Connection (RFC 4254)Open channels: shell, command, file transfer, port forwarding40 – 58The command runs and the output comes back

Two authentications, two different keys

Server authenticationClient authentication
WhenDuring key exchange, frame 12After encryption is on, frame 34

What is signedThe exchange hash HThe session ID (= H) + the request
Who checksClient, using ~/.ssh/known_hostsServer, using ~/.ssh/authorized_keys
