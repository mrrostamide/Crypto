CTF: The Departing Employee

Symmetric Encryption with OpenSSL — AES-128-ECB

Prepared by: MR. Rostami

Scenario

An employee left the company suddenly. Before leaving, they saved a file called challenge.enc on a shared drive. Nobody knows what is inside, or how it was encrypted.

The security team turned this into a training CTF for new hires: recover the file, and find the flag hidden inside. You only have the encrypted file and a list of passwords people commonly reuse. You do not know which cipher was used.

Task 1 — Rules of this challenge

This is a game, not a real investigation. Your goal: recover the hidden text inside challenge.enc and find a string that looks like FLAG{...}.

You already know one tool from the last lab:

bruteforce-salted-openssl -f wordlist.txt -c CIPHER_NAME -K -i 10000 FILE

This time, nobody tells you the cipher. You will need to find it out yourself, step by step.

Remember -K -i 10000 — it tells the tool to derive the key with PBKDF2, matching how the file was encrypted. Without it, every password fails, even the correct one.

Task 2 — Inspect the file first

Before trying anything else, look at the raw bytes of challenge.enc. Open it in GHex and read the first bytes as text, on the right-hand side of the window.

Alternative: use the terminal instead of GHex

If GHex is not available, run:

xxd challenge.enc | head

Look at the ASCII column on the right. The first characters should read a short word, followed by two underscores.

Correct. This confirms challenge.enc was made by OpenSSL's enc command with a salt — the same family of tool as the last lab.

Notice what this header does not tell you: it never says which cipher was used.

Task 3 — Find the cipher and the password

The header confirms the tool, but OpenSSL's enc header never stores the cipher name or key size. Nobody will tell you which one was used — you have to test for it.

A common first guess is AES-256-CBC. Try it against the full wordlist:

bruteforce-salted-openssl -f wordlist.txt -c aes-256-cbc -K -i 10000 challenge.enc

If that does not find a working password, the cipher was something else. Think about what other AES variants exist, and keep testing.

A wrong cipher guess will fail on every password in the list. Keep changing the -c value until one succeeds.

Correct. Same algorithm family as AES-256-CBC, but a different mode and key size — which is exactly why the first guess failed.
That's it. Now you have everything needed to decrypt the file properly.

Task 4 — Decrypt and capture the flag

Using the cipher and password you found in Task 3, decrypt the file for real:

openssl enc -d -CIPHER_NAME -pbkdf2 -in challenge.enc -out flag.txt -pass pass:FOUND_PASSWORD

Replace CIPHER_NAME with whichever cipher worked in Task 3 — the flag follows -d directly, the same way you passed it to bruteforce-salted-openssl with -c.

Open flag.txt. Most of it is filler text. The flag itself is on its own line, near the end, in the form FLAG{...}.

Flag captured. Well done — you identified the tool, found the cipher, cracked the password, and recovered the hidden message.

Why this matters

In this challenge, two things were unknown: the password, and the cipher. OpenSSL's file format never stores which cipher made it — that information has to come from somewhere else, such as documentation, a script, or trial and error. In a real investigation, getting the cipher wrong means every password attempt fails, even the correct one.
