Lab: The Forgotten Password

Symmetric Encryption with OpenSSL — AES-256-CBC

Prepared by: MR. Rostami

Scenario

A freelancer encrypted an important client contract six months ago, using OpenSSL on the command line. They picked a password quickly and never wrote it down. Now they need the contract again for a legal question — but the password is gone.

In this lab, you play both roles. First, you encrypt the file yourself, the same quick and careless way the freelancer did. Later, you play the person trying to recover it, using only the encrypted file and a list of likely passwords.

Task 1 — Understand the tool

Before encrypting anything, you need to know what the command does. OpenSSL's enc command can encrypt a file with a symmetric cipher, using a password instead of a raw key.

openssl enc -aes-256-cbc -pbkdf2 -salt -in contract.txt -out contract.enc -pass pass:MyPassword
  • -aes-256-cbc — the cipher: AES, 256-bit key, CBC mode
  • -pbkdf2 — turns your password into a proper encryption key (slows down guessing attacks)
  • -salt — adds random data so the same password never produces the same key twice

Check your understanding:

What does -pbkdf2 actually do?

Correct. PBKDF2 stretches a password into a proper key, and makes each guess slower for an attacker.
Not quite. Think about what happens between "password" and "encryption key" — PBKDF2 is the step in between.

Why does the command use -salt?

Correct. Without a salt, the same password would always make the exact same key.
Not quite. The salt is about randomness, not size or network safety.

Task 2 — Encrypt the file

Create a short text file called contract.txt with one or two made-up sentences, like a tiny client agreement.

The freelancer in this story picked their password quickly, the way many people do: a simple, easy-to-remember phrase, with no numbers or symbols. For this lab, use exactly this password:

cryptographyiseasy

Encrypt the file:

openssl enc -aes-256-cbc -pbkdf2 -salt -in contract.txt -out contract.enc -pass pass:cryptographyiseasy
Good — this command includes the cipher, PBKDF2, salt, input, output file, and the correct password.

The box turns green once your command includes all the required parts.

Task 3 — Six months later...

Time passes. The freelancer needs the contract for a legal dispute. They open their old notes and realize: the password was never saved anywhere. All that remains is the file contract.enc — and a vague memory of how they usually choose passwords.

From here on, pretend you do not know the password anymore. You only know that it was a plain, everyday phrase — no numbers, no symbols.

Task 4 — Inspect the file first

Before trying to crack anything, check what kind of file this actually is. Open contract.enc in GHex and look at the very first bytes, shown as text on the right-hand side of the window.

Alternative: use the terminal instead of GHex

If GHex is not available, run this command:

xxd contract.enc | head

Look at the ASCII column on the right of the output. The first characters should read a short word, followed by two underscores.

Correct. This confirms the file was made by OpenSSL's enc command with a salt — and it tells you exactly which tool to use next.

Task 5 — Build a wordlist from the habit

You will not use a huge list like rockyou.txt here. Instead, build a small wordlist of plain, everyday phrases — the kind of thing someone types without thinking twice.

Create a file called wordlist.txt with a few guesses, one per line — short phrases or compound words, all lowercase, no numbers or symbols. Make sure the real password from Task 2 is included somewhere in the list. Ten to twenty lines is enough.

nano wordlist.txt
Mark each step once done

✓ Task complete

Task 6 — Try to recover the password

Now use a tool built exactly for this job: bruteforce-salted-openssl. It reads the file's own header and salt, tries every password in your list, and tells you which one works.

The file was made with -pbkdf2, so the tool needs to be told to derive the key the same way, with -K (and -i 10000 to match OpenSSL's default iteration count). Without -K, it uses an older key derivation method, and every password will fail — even the correct one.

bruteforce-salted-openssl -f wordlist.txt -c aes-256-cbc -K -i 10000 contract.enc
Good — this command points the tool at the right cipher, wordlist, and file.

If the password is not found, add a few more guesses to your wordlist and try again.

Task 7 — Decrypt and confirm

Once you have the password, decrypt the file properly:

openssl enc -d -aes-256-cbc -pbkdf2 -in contract.enc -out recovered.txt -pass pass:cryptographyiseasy

Open recovered.txt and compare it to your original contract.txt from Task 2.

Final check

✓ Lab complete

Why this matters

AES-256 itself was never the weak point in this story. The weak point was a plain, predictable phrase used as a password. A short wordlist of everyday phrases was enough to recover it. A long, random password would have made this lab impossible to finish in a classroom — which is exactly the point.
